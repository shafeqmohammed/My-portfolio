01 — Overview

Connectivity you can act on

Armada’s operators monitor satellite-connected terminals across a distributed fleet of remote sites and assets. Connectivity changes constantly. Most changes need no action; a few need it immediately.

The work focused on how operators interpret terminal states, connectivity, alerts, service lines, map density and historical views — so the interface helps them decide, not just observe.

02 — The problem

Plenty of data, not enough decisions

Operational products easily become walls of telemetry: every metric charted, every change an alert, a map that looks impressive but hides what matters. Operators are left asking the same questions over and over:

?Is this terminal actually down, or is it a temporary dip?
?Which of these alerts needs me right now?
?What happened before this, and has it happened before?

04 — What made it difficult

Constraints

01Noisy, delayed signals. Telemetry from remote terminals can be late or missing, so “unknown” is a real state, not an error.
02Map density. Clustered assets make individual problems easy to miss on a map.
03Alert fatigue. One outage can cascade into many notifications.
04Operational risk. A misread state can mean a missed outage at a remote site.
05 — Key decisions

Four decisions that made operations clearer

01

A small, strict state vocabulary

Online, degraded, offline and unknown — each with a written definition, colour, icon and label, so state is never communicated by colour alone.

Trade-off: fine-grained network conditions move into the detail view.

02

Rank alerts by impact, group by cause

Alerts are ordered by affected service lines and duration, and related alerts collapse under their likely cause, so one event reads as one event.

Trade-off: grouping logic must be transparent and easy to expand.

03

Map and list are one view

The fleet map and the terminal list share filters and selection. Dense clusters summarise their worst state, so a problem never hides inside a cluster.

Trade-off: summarising clusters by worst state can look alarming; counts sit beside it.

04

History that explains the present

Each terminal shows the recent signal history that explains its current state, with past incidents marked — instead of every available metric.

Trade-off: power users still need a route to full telemetry.
